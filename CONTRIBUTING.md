# Contributing

Start with the [development guide](docs/product/development.md). Keep the MVP focused on reliable local runs, useful engineering evaluation, and clear evidence.

- Add meaningful tests for task contracts, run recovery, budget accounting, and UI changes.
- Never commit credentials, personal workspace data, or generated paid-run artifacts.
- Keep evaluator changes versioned. Do not overwrite historical evidence or relax checks to manufacture an improvement.
- Document physical assumptions and units when adding a task.
- Use a small Git commit for each coherent change; describe behavior and validation in pull requests.
- Add dependency and dataset attribution before proposing redistribution.

Contributions to project code are under Apache-2.0. Third-party material retains its original terms.
